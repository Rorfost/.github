# Contributing to Rorfost

Thanks for taking the time to contribute. This guide provides the default expectations for Rorfost repositories. Repository-specific guidance takes priority when it is available.

## Before contributing

- Read the repository README and linked docs.
- Check existing issues and pull requests before opening a new one.
- Follow repository-specific instructions when they exist.
- Keep changes related to the problem you are addressing.

## Development

Follow the project's existing code style, formatting, tests, and patterns. Avoid broad refactors or unrelated cleanup unless the change needs them.

## Changes

- Keep changes small and focused.
- Use clear code and names.
- Add comments only when they help explain something.
- Add or update tests when relevant.
- Update documentation when behavior, setup, or usage changes.

## Commits

Use concise, descriptive commit messages. For example:

```text
feat: add request validation
fix: handle empty input
docs: update setup instructions
test: add parser edge cases
refactor: simplify cache handling
```

These are examples, not a requirement. Follow the project's commit style if it has one.

## Pull requests

Explain what changed, why, and how you tested it. Link the related issue when there is one. Keep pull requests focused and easy to review.
